# Findings this product accepts, one per line as `path | CODE | source`, where
# the path is a shell glob and the match is on the line's own text rather than
# its number. The comments are the point of the file: an exemption nobody wrote
# a reason for is not reviewable, and this file is read by the PreToolUse hook
# for file edits (never for commands — a command about to run has no reviewer).
#
# TO RUN THE SCAN:
#
#   bash tools/scan-secret-print.sh
#
# and nothing else, because the version of this header that printed the
# invocation printed it without `--baseline` and so produced 40 findings and
# exit 1 beside the sentence claiming it exits 0. A command in a comment is
# read by people and run by nothing, which is `docs/standards/lessons.md`
# L-A114 one step out: a pre-flight that prints is not a pre-flight that
# blocks. The surfaces now come from `git ls-files` inside that script rather
# than from a glob list here, because the list was two sites short of the trunk
# on the day it was written (`docs/agents/stage.sh`) and had never looked at
# `cli/src/` at all.
#
# 41 findings over 146 tracked files, 13 distinct source lines, every one below.
# They fall into three kinds and the kinds are kept apart on purpose.


# ---------------------------------------------------------------------------
# KIND ONE: the checker is right, and this product keeps the line anyway.
# These are the entries this mechanism is for.
# ---------------------------------------------------------------------------

# `::add-mask::` is how a value is registered with Actions as a thing to mask,
# and registering it requires passing it. There is no form of this that does
# not hand over the value; the alternative is not masking it at all. `$auth` is
# the Langfuse OTLP Basic credential, assembled one line earlier.
.github/workflows/*.yml | X5-PRINT | echo "::add-mask::$auth"

# Writing to `$GITHUB_ENV` is moving a credential into another name, which is
# the form L-X5 explicitly allows; it reaches a file the runner reads and not
# the log. The checker reads `echo` and stops before the redirect.
.github/workflows/*.yml | X5-PRINT | echo "OTEL_EXPORTER_OTLP_HEADERS=Authorization=Basic $auth" >> "$GITHUB_ENV"

# The product's one genuine credential print, and it is a contract rather than
# a mistake. This is the git credential helper `epito` hands to a clone: git
# runs it, says `get` on its stdin, and reads `password=` off its stdout. There
# is no form of a credential helper that does not print the credential, exactly
# as there is no form of `::add-mask::` that does not pass the value — the
# alternative is handing git the token on a command line, where it would reach
# the process table instead of a pipe git owns and closes. Rule 1 two lines
# down ("the only place the value appears") is the invariant this line serves.
#
# This finding is here because the scan now reads `cli/src/`. The glob list
# this file used to carry covered the shell and the workflows and skipped the
# whole CLI, so the one line in this repository the rule is actually about was
# the one line the scan had never seen.
cli/src/lib/runner.js | X5-PRINT | `!f() { if [ "$1" = get ]; then printf 'username=x-access-token\npassword=%s\n' "$${GIT_TOKEN_ENV}"; fi; }; f`;

# A real print of a real token value — and the token is this suite's own stub,
# minted by the stand-in GitHub in section 4 and compared against `$STUB_TOKEN`
# on the next line. Nothing personal and no live credential is ever in it (the
# engineer charter: no real tokens in fixtures), and the print is the
# diagnostic that tells a failing run what the CLI actually put on stdout.
cli/test/smoke-temporal.sh | X5-PRINT | printf '  stdout> %s\n  stderr> %s\n' "$TOKEN_OUT" "$(cat "$ROOT/token.err")"


# ---------------------------------------------------------------------------
# KIND TWO: the checker is wrong, and the fix belongs at HQ.
#
# `tools/check-secret-print.py` is a vendored copy and is not edited here, so
# these sit in the baseline rather than in a patch. Each is reported to the exo
# seat, which owns the vendoring route. WHEN HQ FIXES ONE, DELETE ITS ENTRIES:
# a stale exemption for a bug that is gone hides the next real finding on the
# same line. `docs/agents/x5probe.sh` asks each of these as a question and
# exits 1 while they are still live, so a fix upstream is noticed here rather
# than leaving an exemption standing over a bug that is gone.
# ---------------------------------------------------------------------------

# `${VAR:?word}` is not `${VAR:-word}`. On an unset variable it prints `word`
# to stderr and exits; on a set one it expands to the value, and here that
# expansion is handed to `:`, which discards its arguments and prints nothing.
# This is the correct presence assertion and it is the line six of this
# repository's board helpers open with — addressed.sh, brief.sh, clocks.sh,
# post.sh and reread.sh, 10 sites in five files.
#
# THE FIX IS NOT AN EXEMPTION FOR `:?`, and this entry said otherwise until
# the exo seat proved it in a shell: fed to `:` the expansion prints nothing,
# fed to `echo` it prints the value in full. A blanket exemption for the form
# would open a real leak, and `x5probe.sh` keeps that proof as a probe — see
# KIND THREE. What distinguishes the two is the command the expansion feeds,
# which X5-PRINT already models and X5-DEFAULT does not: X5-DEFAULT needs no
# writer on the line, so the no-op `:` does not save it. Modelling the fed
# command in X5-DEFAULT is the fix; exempting the form is not.
docs/agents/*.sh | X5-DEFAULT | : "${BOARD_RUNTIME_TOKEN:?BOARD_RUNTIME_TOKEN is not set}"

# `$pass` is the count of assertions that passed, printed on the last line of
# every suite in this repository. It is matched because the name contains
# `PASS`, which the checker's name rule reads as `PASSWORD`. 14 sites in 13
# files. The exclusion-suffix rule that already spares `_COUNT` and `_LEN` is
# the shape of the fix, but the name here is the whole word.
#
# Two of the fourteen are in `docs/agents/stage.sh` and were missed when this
# entry was written, because the globs then said `cli/test/*.sh` and
# `deploy/*.sh` and a seat tool prints its tally too. That is why the scan's
# surfaces are a tracked-file set now and not a list.
cli/test/*.sh | X5-PRINT | printf '\nsmoke: %d ok, %d failed\n' "$pass" "$fail"
cli/test/*.sh | X5-PRINT | printf 'smoke: %d ok, %d failed\n' "$pass" "$fail"
cli/test/*.sh | X5-PRINT | printf 'shapes: %d ok, %d failed\n' "$pass" "$fail"
cli/test/*.sh | X5-PRINT | printf '\npack: %d ok, %d failed\n' "$pass" "$fail"
cli/test/*.sh | X5-PRINT | printf '\nstranger: %d ok, %d failed\n' "$pass" "$fail"
deploy/*.sh | X5-PRINT | printf '\nprovision: %d ok, %d failed\n' "$pass" "$fail"
docs/agents/stage.sh | X5-PRINT | if [ "$fail" = 0 ]; then printf 'self-test: %d ok, 0 failed — all verdicts agree\n' "$pass"
docs/agents/stage.sh | X5-PRINT | else printf 'self-test FAILED: %d ok, %d failed — this tool is wrong about built input.\nFix the tool, or the expectation if the contract moved.\n' "$pass" "$fail"; fi

# `key` here is the apt signing key's URL — the function's own signature says
# `<key-url>` — and the line is the error message printed when fetching it
# fails. A public URL, named `key`, in a message whose whole job is to say
# which URL could not be reached. The checker's name rule spares `_URL` and
# `_PATH` suffixes; this name carries neither.
deploy/provision-host.sh | X5-PRINT | echo "provision-host: could not fetch the $name signing key from $key — this host needs outbound https before it can install $name" >&2


# ---------------------------------------------------------------------------
# KIND THREE: the line is a quotation, in a file whose job is to quote.
#
# A probe that asks whether the checker still mismatches a shape has to carry
# that shape as its input, in single quotes, where no shell ever expands it.
# The checker reads text and cannot see the difference, which is correct of it
# and is why this kind exists rather than a marker: these are not findings the
# checker is wrong about and not lines this product keeps against its advice.
# They are the measurement that KIND TWO is still true.
#
# These entries have a shorter life than the others. They go when the entries
# they measure go, because a probe for a bug HQ has fixed is deleted with it.
# ---------------------------------------------------------------------------

# The negative and the positive control for the `:?` finding above, side by
# side, which is the whole argument for not exempting the form: the first
# expansion is handed to `:` and prints nothing, the second is handed to `echo`
# and prints the value. If the checker ever allows the second of these, the
# detector is reporting a fix that is a new leak, and the probe says so.
docs/agents/x5probe.sh | X5-DEFAULT | if ask_command ': "${BOARD_RUNTIME_TOKEN:?BOARD_RUNTIME_TOKEN is not set}"'; then
docs/agents/x5probe.sh | X5-DEFAULT | if ask_command 'echo "${BOARD_RUNTIME_TOKEN:?unset}"'; then

# Incident 3's own line, held as a string so the probe can print the idiom it
# is asking about. It carries two codes because it is two faults at once —
# a `:-` default on a credential name, and a redaction that guesses at a
# prefix — which is why it was the line that leaked: both of its halves are
# shapes L-X5 names, and `github_pat_` matches neither of the prefixes in that
# `sed`. Never executed here; `IDIOM=` assigns it and the probe echoes it.
docs/agents/x5probe.sh | X5-DEFAULT | IDIOM='  echo "EXO_TOKEN set: ${EXO_TOKEN:+yes}${EXO_TOKEN:-NO}" | sed "s/gh[pous]_[A-Za-z0-9]*/REDACTED/"'
docs/agents/x5probe.sh | X5-REDACT | IDIOM='  echo "EXO_TOKEN set: ${EXO_TOKEN:+yes}${EXO_TOKEN:-NO}" | sed "s/gh[pous]_[A-Za-z0-9]*/REDACTED/"'
