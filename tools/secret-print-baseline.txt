# Findings this product accepts, one per line as `path | CODE | source`, where
# the path is a shell glob and the match is on the line's own text rather than
# its number. The comments are the point of the file: an exemption nobody wrote
# a reason for is not reviewable, and this file is read by the PreToolUse hook
# for file edits (never for commands — a command about to run has no reviewer).
#
# Scanned surfaces, which must be named because the checker's own defaults are
# HQ's layout and match almost nothing here:
#
#   python3 tools/check-secret-print.py --name CALLMEBOT_PHONE --name PHONE \
#     .github/workflows/*.yml docs/agents/*.sh docs/agents/*.py \
#     cli/test/*.sh deploy/*.sh
#
# 34 findings, 11 distinct shapes, all of them below. They fall into two kinds
# and the kinds are kept apart on purpose.


# ---------------------------------------------------------------------------
# KIND ONE: the checker is right, and this product keeps the line anyway.
# These are the entries this mechanism is for.
# ---------------------------------------------------------------------------

# `::add-mask::` is how a value is registered with Actions as a thing to mask,
# and registering it requires passing it. There is no form of this that does
# not hand over the value; the alternative is not masking it at all. `$auth` is
# the Langfuse OTLP Basic credential, assembled one line earlier.
.github/workflows/*.yml | X5-PRINT | echo "::add-mask::$auth"

# Writing to `$GITHUB_ENV` is moving a credential into another name, which is
# the form L-X5 explicitly allows; it reaches a file the runner reads and not
# the log. The checker reads `echo` and stops before the redirect.
.github/workflows/*.yml | X5-PRINT | echo "OTEL_EXPORTER_OTLP_HEADERS=Authorization=Basic $auth" >> "$GITHUB_ENV"

# A real print of a real token value — and the token is this suite's own stub,
# minted by the stand-in GitHub in section 4 and compared against `$STUB_TOKEN`
# on the next line. Nothing personal and no live credential is ever in it (the
# engineer charter: no real tokens in fixtures), and the print is the
# diagnostic that tells a failing run what the CLI actually put on stdout.
cli/test/smoke-temporal.sh | X5-PRINT | printf '  stdout> %s\n  stderr> %s\n' "$TOKEN_OUT" "$(cat "$ROOT/token.err")"


# ---------------------------------------------------------------------------
# KIND TWO: the checker is wrong, and the fix belongs at HQ.
#
# `tools/check-secret-print.py` is a vendored copy and is not edited here, so
# these sit in the baseline rather than in a patch. Each is reported to the exo
# seat, which owns the vendoring route. WHEN HQ FIXES ONE, DELETE ITS ENTRIES:
# a stale exemption for a bug that is gone hides the next real finding on the
# same line. `tools/tests/test-hook-wiring.py` asserts the measured behaviour
# of the one that has a detector.
# ---------------------------------------------------------------------------

# `${VAR:?word}` is not `${VAR:-word}`. On an unset variable it prints `word`
# to stderr and exits; on a set one it expands to the value, and here that
# expansion is handed to `:`, which discards its arguments and prints nothing.
# This is the correct presence assertion and it is the line six of this
# repository's board helpers open with — addressed.sh, brief.sh, clocks.sh,
# post.sh and reread.sh, 10 sites. The checker's X5-DEFAULT matches `:?` as
# though it were `:-`, and unlike X5-PRINT it needs no writer on the line, so
# the no-op `:` does not save it.
docs/agents/*.sh | X5-DEFAULT | : "${BOARD_RUNTIME_TOKEN:?BOARD_RUNTIME_TOKEN is not set}"

# `$pass` is the count of assertions that passed, printed on the last line of
# every suite in this repository. It is matched because the name contains
# `PASS`, which the checker's name rule reads as `PASSWORD`. 12 sites. The
# exclusion-suffix rule that already spares `_COUNT` and `_LEN` is the shape
# of the fix, but the name here is the whole word.
cli/test/*.sh | X5-PRINT | printf '\nsmoke: %d ok, %d failed\n' "$pass" "$fail"
cli/test/*.sh | X5-PRINT | printf 'smoke: %d ok, %d failed\n' "$pass" "$fail"
cli/test/*.sh | X5-PRINT | printf 'shapes: %d ok, %d failed\n' "$pass" "$fail"
cli/test/*.sh | X5-PRINT | printf '\npack: %d ok, %d failed\n' "$pass" "$fail"
cli/test/*.sh | X5-PRINT | printf '\nstranger: %d ok, %d failed\n' "$pass" "$fail"
deploy/*.sh | X5-PRINT | printf '\nprovision: %d ok, %d failed\n' "$pass" "$fail"

# `key` here is the apt signing key's URL — the function's own signature says
# `<key-url>` — and the line is the error message printed when fetching it
# fails. A public URL, named `key`, in a message whose whole job is to say
# which URL could not be reached. The checker's name rule spares `_URL` and
# `_PATH` suffixes; this name carries neither.
deploy/provision-host.sh | X5-PRINT | echo "provision-host: could not fetch the $name signing key from $key — this host needs outbound https before it can install $name" >&2
