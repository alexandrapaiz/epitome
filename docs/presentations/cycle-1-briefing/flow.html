2 · What epito deploy will actually do

Manifest in, GitHub App principal out. Five steps, one click.

1

Read and validate agent.toml; refuse anything spec v0.1 refuses.

2

Start a one-shot localhost callback listener, then open GitHub's app-manifest creation page, pre-filled from [identity].scopes.

3

You click Create — the one human click. GitHub redirects back with a temporary code.

4

CLI exchanges the code for the App's id + private key; stores them in .epito/ (0600, gitignored — the manifest stays publishable).

5

Install the App on the target repo. The agent now exists as historian[bot] — a principal that is not you.

Deploy twice = update the same principal, never a duplicate (spec rule 4: identity follows name).
