# All-hands counsel, market seat, 2026-09-20

Owner's question: "so what should we do?" Answered from the market's chair
only. Sources: docs/market.md §5-§8 and the ADRs named inline.
## 1. What the market says we should do next (cycles 1-3, ~6 weeks)
**Cycle 1 (Sep 21 to Oct 2): leave the bets alone.** One market ask inside
bet 1: the `token` subcommand (scope 1c) must be a real public command,
because proposal A (the credential slot for LangGraph, n8n, OpenClaw) is
that command wrapped three ways. Cut audit polish before you cut `token`.

**Cycle 2 (Oct 7 to Oct 20): Slack, born as the first of the messaging
family, with the passport prototype beside it.** Slack wins on all four
ranking laws (§5): self-serve mint, a bot user that is a real someone, and
it is where a human watches the agent work. ADR-11 supplies the customer
(the HQ seats' phase-2 upgrade); proposal D's abstraction ships underneath
so Slack is a family member, not a pick (ADR-9). The passport (proposal B)
rides in the same cycle because it needs two platforms to mean anything,
and GitHub plus Slack are exactly the two. Why this beats LangGraph-first:
a credential object with nowhere to show the identity is invisible; Slack
makes the bot visible, then the package makes it portable. Runtime v0 on
Actions belongs here too, since the HQ dogfood is the launch post. If the
cycle runs long, the passport is not the cut.

**Cycle 3 (Oct 23 to Nov 5): `langchain-epito` plus the OTLP sink, then the
OpenClaw spike.** LangGraph before OpenClaw because its reach is the largest
of any maker (~38.8M monthly downloads, §8.3, secondary), the shape is a
thin package over shipped code (§8.4 part 1), and the listing is a YAML row
the week it is on PyPI. The OTLP sink (§8.4 part 2) gives every LangSmith
user a "which agent did this" filter they do not have, with no LangChain
code in the agent. OpenClaw waits because its foundation is in a declared
"fix the foundation" phase and its brand is radioactive in security circles
(§7.1); we arrive with the passport in hand so we are unmistakably the fix.

Not before cycle 4: Notion (after Slack proves the grammar, §5), Discord
(research only; a messaging sibling and OpenClaw's home), WhatsApp and
WeChat (owner-queued, unranked). Vercel and Supabase stay build-next.

## 2. The one thing to ship before LangChain's next release (ADR-12)
**The passport, public, for one real agent.** LangChain has shipped a
credential feature every month or two (Fleet identity March, Agent Auth
beta, per-caller identity August, Connections Sep 9; §8.2b). Assume the next
lands mid-to-late October, so the deadline is the end of cycle 2, not 3.

"Visible" means: (a) a public URL serving `/.well-known/agent-card.json`
for one HQ seat, signed with the agent's own key, listing its GitHub `[bot]`
and its Slack bot user; (b) a verifier a stranger can run (`epito verify
<card-url>`, or one page with curl and a public key) confirming both are one
agent; (c) a public write-up with the contrast in one line: LangSmith
attributes to a project, a key, or a human; a passport attributes to the
agent itself, checkably, across two platforms. Owner precondition: the repo
is private today, and a passport in a private repo is not visible.

## 3. What to refuse this quarter, and the case against this plan
Refuse: the Vercel listing, a Notion provider, Supabase, A2A marketplaces
(trap T1), agentic payments (T2), the digital-employee enterprise wave (T3),
the adapter runtime (proposal C, phase 2), and any product feature built on
LangSmith's custom-auth or Connections hooks (§8.4 part 3: recipes only).

The strongest argument against my own plan: outside our own n=1, demand for
"the agent as a someone" rather than "the agent as a proxy for a person" is
unmeasured. Every demand quote in the brief is about GitHub, already
shipped, and a first-pass search found no LangChain user asking for a bot
identity per agent (§8.3, flagged). Everything after cycle 1 rests on the
thesis, not a counted signal, and the passport is an invention sequenced
ahead of the plain credential object three communities could use tomorrow.
If the owner weighs counted demand over thesis, swap cycles 2 and 3.

## 4. Three recommendations (accept or reject one by one)

1. In cycle 2, put our agents on Slack and give one of our own company's
   agents a public, signed page proving its GitHub account and its Slack
   account are the same agent, published before mid-October, which means
   making the repo public first.
2. In cycle 3, ship the small LangChain package that lets any LangGraph
   agent fetch its own short-lived token at run time, and list it in
   LangChain's integrations table the same week it is on PyPI.
3. Say no this quarter to Vercel, Notion, Supabase, payments, and enterprise
   agent marketplaces, and treat OpenClaw as a spike that starts only after
   the LangChain package works.
