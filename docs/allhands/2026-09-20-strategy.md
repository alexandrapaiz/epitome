## Where the three chairs agree

   (deploy-identity-v0) or bet 2 (MCP server). Market adds one
   sharpening: `epito token` must be a real public command, because it
   is proposal A's whole substance.
2. **The passport is the outdo arm and it moves beside Slack, not
   behind it** (ADR-12). All three seats sequence cycle 2 as: Slack as
   the first MessagingProvider + the passport prototype, with HQ's
   seats as customer #1 (ADR-11).
3. **Cycle 3 is the LangChain package** (`langchain-epito` + OTLP
   attribution), listed in LangChain's integrations table the week it
   is on PyPI; OpenClaw is a spike that starts only after it works.
4. **Refuse this quarter**: Vercel, Notion, Supabase, payments,
   enterprise agent marketplaces (market); the full toolchain
   migration inside cycle 1, `jose` (use `node:crypto`), any build on
   LangSmith's hosted auth (engineer).
5. **Runtime v0 as shaped violates the envelope law** (okr's drift
   check): it would ship a container running an agent WE wrote.
   Reshape it as bring-your-own-agent before cycle 2 bets it.

## Where they differ, and the chair's read

- **Passport visibility by mid-October.** Market wants a public,
  signed page for one HQ seat proving GitHub and Slack are the same
  agent, before LangChain's next release. Engineer says: cycle 2 yes
  for the GitHub arm (two runs: `epito passport` + `epito passport
  verify`), but the two-platform proof needs the Slack principal,
  which is cycle 2's big batch itself; it closes end of cycle 2 only
  if Slack's mint lands by week 1, else cycle 3. Chair's read: ship
  the GitHub arm early in cycle 2 and publish the write-up on the
  mechanism; call it two-platform only when it is. A true single-
  platform passport before mid-October still beats their vault.
- **The network-path problem** (hosted agents reaching our token
  issuer). Engineer: already answered by runtime v0's own shape — an
  Actions runner has no `.epito/`, so the agent's PEM travels as a
  short-lived secret and the 1h token is minted in-container; the
  same works for any host with a secrets field; no token server
  before phase 3; cost = local audit goes blind to hosted runs until
  an OTLP sink exists. OKR had asked that this be named, not drifted;
  it is now named. Chair's read: adopt; record as the architecture's
  answer.
