## 1. A charter is three files, and nobody had diffed them

Full rule and evidence: L11. The sweep, per seat — `prompts/` against
the workflow's inline `prompt:` block against `buildPrompt` in
`cli/src/lib/runner.js`:

| Instruction | `prompts/` | workflow block | runtime dispatch |
|---|---|---|---|
| branch convention | named in none of the six charters | `<seat>/YYYY-MM-DD-slug`, hardcoded in all five | `<agent-name>/<date>-<trigger>`, `runner.js:71` |
| may it edit a charter | exo's central duty is charter patches | "never edit charters" (all five) | silent; forbids secrets and workflows only |
| draft-PR-first | in no charter | present, all five | present |
| exactly one PR | in no charter | present, all five | present |
| turn cap, model | in no charter | explicit `--max-turns`, `--model` | decided by `router.js` |

Two divergences with teeth (the branch name, the charter-edit
prohibition) and three rules that live only in launchers, which is the
inverse of L-X10: the launcher should carry the pointer and the charter
the rule. `docs/agents/workflow-template.yml` — the file new seats are
stamped from — reproduces both divergences, so this is a template
defect, not five drifted files.

**One decision for the owner, because it is not this seat's to make.**
Which convention is canonical? Recommendation: the runtime's
`<agent-name>/<date>-<trigger>`. It is already the majority in this
repo's PR list (five of today's PRs), it encodes how the run was woken,
and it namespaces by company. Cost: one centralizer PR touching the
five workflow prompt blocks and the template; every seat branch becomes
`epitome-*`. The alternative — keep `<seat>/…` and change `runner.js:71`
— is one product-code line plus its test, and it throws away the
trigger in the name. Either is fine; two is not.
