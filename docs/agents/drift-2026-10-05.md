## 2. The landing loop

Five engineer runs in five days produced five pull requests whose
subject is the same unmerged chain of work: #37 composed three
branches, #40 composed five, #45 composed nine, #48 verified the
composition from a cold box, and #51 exists because the composition
went stale again. Each one correctly says it is not building a new
card. Each one adds a link to the queue it is draining.

Verified from this box rather than taken from the pull request bodies:

```
$ for n in 28 33 36 37 38 40 41 43 44 45 46; do
    git merge-base --is-ancestor pr$n pr48 && echo "#$n IN pr48"; done
#28 IN pr48   #33 IN pr48   #36 IN pr48   #37 IN pr48
#38 IN pr48   #40 IN pr48   #41 IN pr48   #43 IN pr48
#44 IN pr48   #45 IN pr48   #46 IN pr48

$ git merge-base --is-ancestor main pr48 && echo yes || echo "main NOT in pr48"
main NOT in pr48
$ git merge-base --is-ancestor main pr51 && git merge-base --is-ancestor pr48 pr51 \
    && echo "pr51 carries main and pr48"
pr51 carries main and pr48
```

So twelve of the engineer's open pull requests are one linear chain, and
the single branch that carries both the chain and current `main` is #51,
opened in this same window. Merging that one lands all twelve.

**The cost, measured.** #48 verified the whole stack green from a cold
box and recorded the transcript at 02:27Z. The lessons sync (#47) merged
at 02:28Z. One minute later the verification described a tree that was no
longer the merge candidate, which is why #51 exists. The only merge in
five days is what invalidated five days of verification, and it will
happen again on the next merge of anything.

**Where the loop ends, and why it cannot end inside the engineer's
lane.** The engineer charter's rule is correct for the case it was
written from: in #24 a deep unmerged stack was landed instead of added
to, and that worked. What the clause has no words for is the second
time. Completing a landing needs a merge, the engineer may never merge
its own work, and the role that would hold the gate is proposed in #29,
open since 2026-09-30. The escape hatch for the queue is in the queue.
That is L13, and the patch that gives the clause a stopping point is in
`docs/agents/patches/`.
