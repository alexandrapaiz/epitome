## 1. The clock moved to the host, and thirty-three of thirty-eight seats did not get one

On 2026-10-17 every seat workflow in this repository had its schedule
retired, and the line that replaced it says why, in the file:

```
# schedule: retired 2026-10-17 (HQ decision 056): every seat's clock is
# its manifest on the host; GitHub is an event source, not a runtime
```

That is a sound decision and the manifests in this repository hold the
right side of the bargain. `agents/engineer/agent.toml` carries
`cron = "46 11,23 * * *"`, the owner's twice-a-day directive;
`agents/pm/agent.toml` carries `cron = "0 12 * * 1"`, the Monday
ceremony; market carries Friday noon and okr carries the first of the
month. The translation was done carefully and it is correct.

The host does not read those files. It runs `epito run /srv/asc/roster`
(`/etc/systemd/system/epitod.service`), and `/srv/asc/roster` is a
separate copy of the roster that is not in any of the product
repositories. Read from inside this window, every manifest on it:

| Company | Seats on the roster | Carrying a cron |
|---|---|---|
| alexandria | 12 | 0 |
| ursa | 11 | 0 |
| epitome | 6 | 1 — `frontend`, the dormant template |
| HQ, company-wide seats | 9 | 4 — engineer, exo-centralizer, finance, okr |
| **total** | **38** | **5** |

So epitome's engineer, project manager, market, okr and ExO seats have
`webhook = true` and no `cron` line at all, and the installed runtime's
only clock is that line: `cli/src/lib/manifest.js:46` accepts a manifest
with a webhook and no cron, and `cli/src/lib/cron.js` is the only thing
that fires a run on time. A webhook-only seat runs when something sends
it an event, and never otherwise. The one epitome seat with a clock on
the host is the eleven-line template that does no work.

What that costs, each item checkable rather than argued:

- This review is thirteen days late because nothing fires it. Both of
  the previous two drift reviews were started by hand.
- The engineer's twice-a-day cadence, an owner directive of 2026-09-24,
  exists in this repository and nowhere that executes.
- The market brief's Friday window last ran on Actions on 2026-10-16,
  before the retirement. Nothing will fire the next one.
- The quarterly grading's monthly run on the first of the month has no
  clock, so 2026-11-01 will pass without it.
- Tomorrow, 2026-10-19, is a Monday, and the project manager's Monday
  ceremony — the one that sets the sprint's name and goal on the board,
  company standard section 14 — has no clock to fire it. That is a
  prediction, and the next run of this seat should check it.

**Not a drift, stated so nobody counts it as one.** The seats did run
today: twenty-five run reports on this company's board between 01:30 and
09:01 UTC. Every one of them was woken by an event. The bus works, and
it is now the only clock this company has.

**Why this is a handoff and not just an entry.** `/srv/asc/roster` is on

## 2. Three and a half days when the building seat did not start

Nine runs failed in the window. Eight of them belong to the engineer,
one to the project manager, and they run from 2026-10-12T20:25Z to
2026-10-16T01:41Z. Each one failed in three to five seconds with zero
steps executed, which is not a seat failing at its work; it is a job
that never began.

`gh run view --log-failed` returns `log not found` for all nine, because
a job that never started wrote no log. Successful runs from the same two
days return eighty kilobytes each, so this is not retention. The cause
is in a surface no charter and no standard names, the job's check-run
annotation, and it is the same sentence on every one of the nine:

> The job was not started because recent account payments have failed or
> your spending limit needs to be increased. Please check the 'Billing &
> plans' section in your settings

Two engineer runs on 2026-10-16 and 2026-10-17 succeeded, so the block
cleared without anyone recording that it had been there. Full record,
with the impact and the root cause in the triage procedure rather than
in a seat: incident 6.

## 3. "One draft pull request per run", when a run became a message

The project-manager charter's output clause is one line: *One draft PR
per run.* It was written for a seat whose charter's opening sentence
says "You run weekly, and on dispatch". Since the bus became the clock,
a run is a message. Measured on today alone, from the board's run
reports and this repository's pull requests:

| | |
|---|---|
| host runs reported for this company today | 25 |
| of those, the project manager's | 20 |
| its pull requests opened today | 24 |
| its pull requests still open | 18 |
| of this company's 22 open pull requests, its share | 18 |

Eighteen is also the number I could not merge. Each of those eighteen
branches is clean against `main` on its own — `git merge-tree` says so
for all eighteen. Merged in sequence into a throwaway worktree, in the
order they were opened, exactly two go in and sixteen conflict, every
one of them on `docs/backlog.md`:

```
#155 merged ok (1)
#157 CONFLICT (after 1 merges)
...
merged in sequence: 2 of 18
```

They conflict because each pass appends its narrative to the same place
in the same file. `docs/backlog.md` has gone from 97 lines on 2026-10-05
to 338 today, and of the 170 lines under `## Now` two pass logs occupy
62, in a file whose own third line says "Cards are readable,
self-sufficient, and name a seat" — a pass log names no seat, and the
two here carry twenty pull request numbers between them, eight distinct.

Nobody disobeyed anything. The charter promised one pull request per
run, the standard made a message a run, and the promise kept itself
twenty times in nine hours. That is lesson L16, and the patch that gives
the clause a unit that does not move when the trigger does is in
`docs/agents/patches/`.

**What this costs on the surface this register cares most about.** The
lesson this org wrote two weeks ago about owner-facing pull request
descriptions worked, and the numbers say so plainly: decision-record
codes in the opening ten lines of a body ran at 3.6 per artifact across
the last review's twelve, and at 0.27 across this window's 136. What
replaced them is cross-reference to other pull requests — 462 in the
opening ten lines across the window, and 18 of the 21 window titles
carrying a pull request number belong to one seat's passes. The defect
is no longer the vocabulary. It is that the queue she reads is now
four-fifths bookkeeping, and no rewording fixes that; only the unit
does.
